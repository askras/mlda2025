# Методическмие рекомендации по написанию курсовой работы

Всего представлено **100 тем** для курсовых работ. Темы сгруппированы по типам задач, для каждой
указаны цель, актуальность, набор данных, его описание и рекомендации по содержанию.
Отдельным блоком в каждой теме даны рекомендации по выбору критерия качества модели:
несколько вариантов метрик с пояснениями, обоснование выбора для конкретного набора
данных и типичная ошибка при оценке.

Сводная таблица с распределением тем по сложности и объёму данных — в файле
[`topics_table_ml.md`](topics_table_ml.md).

Все наборы данных проверены на доступность. Датасеты с [UCI ML Repository](https://archive.ics.uci.edu/)
загружаются пакетом `ucimlrepo`, остальные — через `fetch_openml`.

---

## 1. Порядок действий

1. Выберите тему, которая вам интересна, и согласуйте её с преподавателем.
2. Установите библиотеки: `pip install ucimlrepo openml datasets transformers prophet`.
3. Скачайте данные, воспроизведите разведку и убедитесь, что понимаете природу каждого признака.
4. Реализуйте пайплайн от сырых данных до отчёта с метриками.
5. На защите должны быть ответы на все вопросы из чек-листа в разделе 10.

Темы внутри одной группы равноценны по трудоёмкости. Темы из разных групп отличаются не только
типом задачи, но и объёмом данных: от 690 строк (Credit Approval) до 2.5 млн строк
(US Census Data 1990, Household Electric Power Consumption).

## 2. Требования к структуре курсовой

Работа должна содержать следующие разделы. Объём кода — не менее 300 строк,
объём текста с анализом — не менее 15 страниц.

| Раздел | Что должно быть |
|---|---|
| Постановка задачи | Формулировка в терминах бизнеса или науки, почему задача важна, что именно предсказываем |
| Описание данных | Источник, объём, типы признаков, целевая переменная, известные ограничения |
| Разведочный анализ | Распределения цели и признаков, пропуски, выбросы, корреляции, визуализации |
| Предобработка | Кодирование категорий, обработка пропусков, масштабирование, балансировка, генерация признаков |
| Моделирование | Не менее 5 моделей, включая простой базис (dummy / линейная) |
| Оценка качества | Корректное разделение, метрики, статистическая значимость различий |
| Интерпретация | Важность признаков, ошибки модели, примеры предсказаний |
| Практическая часть | Собранное приложение (Streamlit, REST API, ноутбук) либо сценарий внедрения |
| Выводы | Что модель умеет, чего не умеет, как её можно улучшить, где применить |

Обязательные требования:

- Все модели обучаются на одной и той же разбивке данных, чтобы их можно было корректно сравнивать.
- Гиперпараметры подбираются через `GridSearchCV`/`RandomizedSearchCV`/`Optuna` с `cv` внутри
  обучающей выборки, тестовая выборка используется **один раз** в самом конце.
- Есть хотя бы один конкурентный baseline (константа, простая эвристика, линейная модель).
- Код оформлен в ноутбуке (Jupyter) или модульном виде, запускается от начала до конца.
- Результаты воспроизводимы: зафиксированы seed, версии библиотек, параметры моделей.

## 3. Шкала сложности

Каждая тема помечена одним из трёх уровней. Уровень влияет на ожидаемую глубину работы,
а не на количество кода.

| Уровень | Признаки темы | Что ожидается сверх базового |
|---|---|---|
| 🟢 1 — базовая | Мало данных (до 2 000 строк), признаки преимущественно числовые, нет пропусков или пропусков мало | Корректная разбивка, 5–7 моделей, сравнение метрик, выводы по важности признаков |
| 🟡 2 — средняя | 2 000–200 000 строк, есть категориальные признаки, пропуски, несбалансированные классы | Инженерия признаков, работа с дисбалансом (SMOTE, веса классов, порог), вложенная CV или отдельный валидационный набор, анализ ошибок |
| 🔴 3 — сложная | 200 000+ строк, временные ряды, текст или изображения, либо сильный дисбаланс | Инженерия признаков для временных рядов / текста / изображений, кастомные метрики качества, устойчивость модели, статистическая значимость различий (bootstrap, тест Моргана), глубокое обучение или AutoML |

## 4. Шпаргалка по метрикам качества

### Классификация

Ситуация выбирается по соотношению классов и цене ошибки.

| Ситуация | Основные метрики | Почему |
|---|---|---|
| Классы примерно равны | Accuracy, F1-score (macro), матрица ошибок | Accuracy достаточно информативна |
| Дисбаланс 10:1 … 100:1 | F1-score (для положительного класса), PR-AUC | Accuracy всегда близка к доле большинства; ROC-AUC завышает качество |
| Дисбаланс сильнее 100:1 | PR-AUC, Recall@top-K, доля верно найденных среди top-K | Нужна ещё и мера полезности для аналитика |
| Цена пропуска опазна (болезни, мошенничество) | Recall (чувствительность), F-beta при beta > 1 | Ложные отрицания дороги |
| Цена ложной тревоги дорога (блокировка чека) | Precision, F-beta при beta < 1 | Лучше пропустить, чем заблокировать честного клиента |
| Порог решения меняется в проде | PR-кривая, подбор порога под целевой Recall или Precision | Порог — часть модели, а не гиперпараметр sklearn |


### Регрессия

MAE, RMSE, R², MAPE (осторожно — MAPE взрывается, когда целевая переменная близка к нулю),
медианная абсолютная ошибка (устойчива к выбросам, в отличие от MAE в абсолютных единицах).
Всегда указывайте единицы измерения целевой переменной: MAE = «средняя ошибка 0.8 кг».

### Кластеризация

Метрики качества кластеризации либо внутренние (силуэт, коэффициент Дэвида–Болдуина, Calinski–Harabasz,
стабильность по bootstrap), либо внешние (adjusted Rand index, homogeneity/completeness/v-measure),
если разметка известна, но не использовалась при обучении. Дополнительно оценивайте интерпретируемость:
профили кластеров в виде таблицы «средние значения признаков по кластерам».

### Временные ряды

MAE, RMSE, MAPE, SMAPE — по горизонту упреждения. Сравнивать с наивным прогнозом
(`предыдущее значение`, `скользящее среднее за 24 ч`) — без этого сравнения качество не интерпретируется.
Для вероятностных моделей дополнительно считайте CRPS или pinball loss на нескольких квантилях.

### Текст и изображения

Текст: accuracy/F1 + отдельный разбор ошибок по длинам отзывов и по темам. Изображения: accuracy/F1
наряду с матрицей ошибок и визуализацией `Grad-CAM` (показывает, куда смотрит модель).

## 5. Как загружать данные

### UCI ML Repository
<!-- #endregion -->

```python
# pip install ucimlrepo
from ucimlrepo import fetch_ucirepo

wine = fetch_ucirepo(id=186)    # 
X = wine.data.features          # DataFrame с признаками
y = wine.data.targets           # DataFrame с целевой переменной
variables = wine.data.variables # словарь: имя, роль, тип, пропуски
meta = wine.data.metadata       # число строк, признаков, классы задач
```

Полный список наборов: `ucimlrepo.list_available_datasets()`.


### OpenML

```python
from sklearn.datasets import fetch_openml

adult = fetch_openml(data_id=1590, as_frame=True)  # 48 842 строки, категории в object
```

### Текст и изображения средствами классических методов

Для текста — `TfidfVectorizer` или `HashingVectorizer` вместе с линейной моделью;
для изображений — признаки `HOG`, `LBP`, цветовые гистограммы и дескрипторы
`SIFT`/`ORB`. Если задача всё же требует нейросети, переходите к набору
[`topics_ai.md`](topics_ai.md).

## 7. Как выбрать тему и что делать, если данных нет

Если предложенные наборы вам не подходят, алгоритм такой:

1. Найдите данные на [UCI ML Repository](https://archive.ics.uci.edu/datasets),
   в [OpenML](https://www.openml.org/search?type=data), на Kaggle или в HuggingFace.
2. Проверьте, что данные содержат **целевую переменную** — иначе задача не будет
   сформулирована. Если цели нет, но есть признаки описания объектов (например,
   транзакции), тема переформулируется в кластеризацию или в поиск аномалий.
3. Проверьте лицензию и размер файла. Данные объёмом более 500 МБ лучше не брать:
   обучение не поместится в учебную работу, а её загрузка займёт время.
4. Сформулируйте цель одним предложением: «предсказать X по признакам Y» либо
   «выделить K групп объектов по признакам Z».
5. Проверьте, что целевых событий достаточно: минимум 30–50 объектов на класс,
   иначе метрики будут нестабильны.

Проверка на утечку — обязательный шаг до начала работы. Посмотрите на описание
признаков: если какая-то колонка является следствием целевой переменной
(«исход после лечения», «количество жалоб за год» при цели «жалобы за год»),
её нужно удалить, даже если без неё качество заметно ниже.

## 8. Типичные ошибки

| Ошибка | Почему это плохо | Что делать правильно |
|---|---|---|
| Разбиение данных до нормализации и кодирования | Тестовая выборка участвует в построении словаря категорий и в расчёте статистик | Все преобразования — внутри `Pipeline`, обучение только на train |
| Случайное разбиение временного ряда | Будущие значения попадают в обучение, качество завышено | Разбивать строго по времени, с отложенным тестовым периодом |
| Accuracy как единственная метрика при дисбалансе | Модель, всегда предсказывающая majority-класс, получает высокую accuracy | PR-AUC, F1 положительного класса, матрица ошибок |
| Подбор гиперпараметров на тестовой выборке | Оценка качества смещена, результат не воспроизводится | Отдельная валидация или вложенная кросс-валидация |
| Один случайный сплит при малом объёме | Разброс метрик достигает 10–20 % | `RepeatedStratifiedKFold` и доверительные интервалы |
| Забыта утечка через временную метку | Модель использует не те признаки, что доступны в проде | Анализ важности, проверка достижимости признака в момент предсказания |
| Оценка на сырых категориальных кодах | Деревья работают хуже, SVM не работает вовсе | One-hot, ordinal-кодирование, `CatBoostEncoder` |
| Нет базовой модели | Непонятно, даёт ли выигрыш сама модель | `DummyClassifier`, `DummyRegressor`, наивный прогноз |
| Метрика без единиц измерения | Невозможно понять, хорошо ли это | «MAE = 0.8 кг» лучше, чем «MAE = 3.2» |

- [ ] Указан источник данных и приложена документация к набору.
- [ ] Признаки исследованы: распределения, пропуски, выбросы, корреляции.
- [ ] Проверена утечка данных, описано, какие признаки были отброшены и почему.
- [ ] Все преобразования выполняются внутри `Pipeline`, обучаются на train.
- [ ] Есть базовая модель, с которой сравниваются все остальные.
- [ ] Обучено не менее пяти моделей, подобраны гиперпараметры.
- [ ] Тестовая выборка использована один раз, в самом конце.
- [ ] Приведены метрики, уместные для типа задачи, с единицами измерения.
- [ ] Проведён анализ важности признаков и разбор ошибок модели.
- [ ] Есть практическая часть: приложение или сценарий внедрения.
- [ ] Сформулированы ограничения модели и направления её улучшения.
- [ ] Код запускается от начала до конца, результаты воспроизводимы.
- [ ] Оформление соответствует требованиям курса, графики читаемы, подписи на русском.
